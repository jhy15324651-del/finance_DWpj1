## 📰 뉴스&트위터 시연 (약 3분)

### 1️⃣ 뉴스 수집 설계 – 법적·운영적 판단 (약 1분)

**"금융 뉴스 수집에서 가장 먼저 고민했던 것은**
**법적 리스크와 신뢰성 문제였습니다."**

"네이버나 주요 언론사를 크롤링하면
빠르고 많은 데이터를 얻을 수 있지만,
저작권 문제와 차단 위험이 있었습니다."

"그래서 공식적으로 외부 제공이 허용된
**RSS 기반 뉴스 수집 방식**을 선택했고,
신뢰도와 영향력을 기준으로
**Yahoo Finance, Reuters, Bloomberg 등
5개 사이트를 선정**했습니다."

---

### 2️⃣ 자동화와 번역 – 스케줄러와 GPT (약 1분)

**"뉴스는 매일 오전 10시에 자동으로 수집됩니다."**

"하지만 영어 뉴스를 한국 사용자에게 제공하려면
번역이 필수였습니다."

"처음에는 Papago나 Google Translate를 고려했지만,
**금융 전문 용어의 정확도가 떨어졌고**,
특히 'Fed rate hike'나 '13F filing' 같은 표현이
맥락 없이 직역되는 문제가 있었습니다."

"그래서 **GPT API의 translateNewsToKorean 메서드**를 사용해
맥락을 이해한 번역을 제공하고,
**원문도 함께 저장하여**
빠른 이해와 정확한 해석을 동시에 가능하게 했습니다."

---

### 3️⃣ 아카이브와 관리 – 데이터 생명주기 (약 1분)

**"뉴스는 시간이 지나면 가치가 떨어집니다."**

"그래서 **24시간이 지난 뉴스는 자동으로 아카이브 처리**되고,
메인 화면에서는 숨겨집니다."

"하지만 완전히 삭제하지 않고
**주간 단위로 주간 뉴스로 재구성**하여
사용자가 지난 일주일의 중요 뉴스를 한눈에 볼 수 있게 했습니다."

"조회수 기반 랭킹 시스템을 통해
**상위 5개 뉴스는 메인 화면 사이드바에 노출**되어
가장 관심 있는 이슈를 먼저 확인할 수 있습니다."

*(시연: 뉴스 목록 → 개별 뉴스 클릭 → 원문/번역 토글 → 아카이브 표시)*

---

### 4️⃣ 트위터 인사이트 – 비용과 가치의 균형 (약 1.5분)

**"트위터 API는 월 100달러부터 시작하고,**
**실시간 수집은 월 5,000달러가 넘습니다."**

"프로젝트 예산으로는 감당할 수 없는 금액이었고,
무료 크롤링은 법적 리스크가 컸습니다."

"그래서 **관리자 수동 등록 방식**으로 설계했습니다.
중요한 투자대가의 트윗을
관리자가 선별하여 등록하면,
원문과 번역, 링크를 함께 저장합니다."

"이 방식은 비용은 0원이지만,
**신뢰도와 품질은 더 높습니다.**
왜냐하면 관리자가 직접
금융 관련 주요 트윗만 선별하기 때문입니다."

*(시연: 트위터 인사이트 → 더미 데이터 확인 → 관리자 페이지 → 새 트윗 추가 모달)*

---

### 5️⃣ 관리자 페이지 – 뉴스 관리와 통제 (약 1분)

**"관리자 페이지에서는 뉴스와 트위터를 통제합니다."**

"뉴스 관리 탭에서는
**수동 크롤링 실행**, **번역 안 된 뉴스 재번역**,
**부적절한 뉴스 삭제**가 가능합니다."

"삭제는 **소프트 삭제 방식**으로 동작합니다.
즉시 물리 삭제하지 않고
**isDeleted 플래그를 true로 설정**하고,
**삭제 사유, 관리자 정보, IP 주소를 감사 로그에 기록**합니다."

"30일 이후 자동으로 하드 삭제되지만,
그 전까지는 복구가 가능하고
**누가, 언제, 왜 삭제했는지 추적**할 수 있습니다."

"이렇게 설계한 이유는
금융 플랫폼에서는 **즉시 삭제보다
기록과 추적이 더 중요**하다고 판단했기 때문입니다."

*(시연: 관리자 페이지 → 뉴스 관리 → 수동 크롤링 버튼 → 삭제 모달 → 삭제 사유 입력)*

## 📊 포트폴리오&투자자비교 시연 (약 5분)

### 1️⃣ 문제 정의 – 왜 AI API로 쉽게 해결하지 않았는가 (약 1.5분)

**"처음 설계 단계에서는**
**AI API를 활용해 빠르게 구현할 수 있었습니다."**

"사용자가 포트폴리오 스크린샷을 올리면
GPT Vision이나 Claude가
종목과 비중을 추출해주고,
비슷한 투자대가를 추천해주는 방식이었습니다."

"하지만 설계 관점에서 다시 생각해 보게 되었습니다."

"사용자가 약 1,000명만 되어도
하루에 두 번씩 분석을 요청한다고 가정하면,
**월간 약 80만 원, 연간으로는 1,000만 원**에 가까운 비용이
순수 유지 비용으로 발생합니다."

"이 비용은 수익이 아니라
단순히 서비스를 유지하기 위한 비용입니다."

"그래서 **외부 API 의존도를 줄이고,**
**내부에서 처리 가능한 구조를 직접 설계**하기로 했습니다."

---

### 2️⃣ OCR 파이프라인 – Tesseract와 전처리 (약 1.5분)

**"그 과정에서 선택한 것이**
**Tesseract OCR 기반 포트폴리오 추출**이었습니다."**

"사용자가 증권사 앱 스크린샷을 업로드하면,
먼저 **OpenCV로 이미지 전처리**를 합니다.
그레이스케일 변환, 이진화, 노이즈 제거를 거쳐
**OCR 인식률을 20~30% 향상**시킵니다."

"그 다음 **Tesseract ThreadLocal 인스턴스**로
멀티스레드 환경에서도 안전하게 텍스트를 추출합니다."

"하지만 여기서 문제가 있었습니다.
**한국 증권사는 종목명을 한글로 표시**하는데,
13F 보고서는 영어 티커로 기록되어 있습니다."

"그래서 **TickerMappingService**를 만들어
'애플' → 'AAPL', '테슬라' → 'TSLA'로 변환하고,
**정규화 매핑**으로 '삼성 전자', '삼성전자', '삼성전자(우)'
모두 같은 종목으로 인식하게 했습니다."

*(시연: 포트폴리오 분석 → 이미지 업로드 → 증권사 선택 → OCR 결과 확인)*

---

### 3️⃣ 13F 데이터 매칭 – SEC API와 비동기 수집 (약 1.5분)

**"OCR로 사용자 포트폴리오를 추출했다면,**
**이제 투자대가 포트폴리오와 비교해야 합니다."**

"미국의 대형 투자자들은 분기마다
보유 종목을 **13F 보고서로 의무 제출**합니다."

"워렌 버핏, 레이 달리오, 캐시 우드 같은
투자대가들의 실제 포트폴리오를 SEC API에서 가져올 수 있습니다."

"하지만 **SEC API는 초당 10회 제한**이 있어
50명의 투자대가 데이터를 수집하면
최소 5분 이상 걸립니다."

"그래서 **@Async 비동기 처리**로 백그라운드에서 수집하고,
**RateLimiter로 초당 9회로 제한**하여 429 에러를 방지했습니다."

"또한 **Checkpoint Resume 기능**으로
서버 재시작 시 성공한 투자자는 건너뛰고
실패한 투자자만 재수집하도록 했습니다."

*(시연: 관리자 페이지 → 포트폴리오 관리 → 13F 데이터 수집 시작 → 진행률 확인)*

---

### 4️⃣ 유사도 계산 – 코사인 유사도와 가중치 (약 1.5분)

**"이제 사용자 포트폴리오와**
**투자대가 포트폴리오를 비교해야 합니다."**

"여기서 두 번째 문제가 발생했습니다.
**같은 종목을 보유하고 있더라도**
**비중이 크게 다를 수 있기 때문에**
단순 매칭은 의미가 없었습니다."

"예를 들어 사용자는 애플 50%, 테슬라 20%인데
투자대가는 애플 10%, 테슬라 5%라면
종목은 같지만 전략이 완전히 다릅니다."

"그래서 **코사인 유사도 기반 가중치**를 적용했습니다.
종목의 존재 여부뿐 아니라
**비중의 방향성과 크기까지 반영**하도록 설계했습니다."

"최종 매칭 점수는
**코사인 유사도 40%,**
**종목 겹침 비율 40%,**
**상위 5개 종목 겹침 점수 20%를**
가중 평균하여 계산합니다."

"이 비율은 여러 테스트를 통해
**사람의 직관과 가장 비슷한 결과**를 내는 값으로 조정했습니다."

*(시연: 포트폴리오 분석 결과 → TOP 3 투자대가 표시 → 매칭 점수 확인)*

---

### 5️⃣ 투자자 비교 – 검증과 다양성 (약 1.5분)

**"이제 이렇게 정제된 데이터를**
**검증하는 단계가 필요했습니다."**

"검증 세션에서는
**최대 4명의 투자자를 선택**해
투자 철학을 비교할 수 있습니다."

"워렌 버핏은 **가치투자와 장기 보유**,
캐시 우드는 **혁신 성장주 중심**,
레이 달리오는 **분산과 리스크 관리**를 강조합니다."

"각 투자자의 투자 철학은
현재는 제가 직접 정리한
**특징 기반으로 제공**되고 있습니다."

"4명의 투자자를 선택해
**포트폴리오 생성 버튼**을 누르면,
마치 이 투자자들이 회의를 한 것처럼
**10개의 포트폴리오가 도출**됩니다."

"이 결과는 **Gemini API에 프롬프트를 전달**해 생성되며,
**원형 비율 이미지로 시각화**됩니다."

"여기서 중요한 점은
**AI는 결정을 대신하는 존재가 아니라,**
**판단을 검증하고 비교하는 도구**로 사용했다는 것입니다."

*(시연: 투자자 비교 → 4명 선택 → 포트폴리오 생성 → AI 응답 확인 → 원형 차트 시각화)*

---

### 6️⃣ Exposure 정규화 – 레버리지 ETF 처리 (약 1분)

**"마지막으로 한 가지 더 고려한 것이**
**레버리지와 인버스 ETF 문제**였습니다."**

"예를 들어 TQQQ는 나스닥 3배 레버리지 ETF인데,
10% 보유는 실제로 **QQQ 30% 노출**과 같습니다."

"이를 고려하지 않으면
**실질적인 리스크가 왜곡**됩니다."

"그래서 **PortfolioExposureNormalizer**를 구현해
레버리지 배율을 기초자산 노출로 환산하고,
**정규화된 포트폴리오로 유사도를 계산**하도록 했습니다."

"이렇게 하면 TQQQ 10%와 QQQ 30%를
실질적으로 같은 포지션으로 인식할 수 있습니다."

*(시연: 포트폴리오 상세 → 레버리지 ETF 표시 → Exposure 환산 값 확인)*

## 📌 시연 흐름 요약

### 뉴스&트위터 (3분)
1. 뉴스 목록 확인 → 개별 뉴스 상세 (원문/번역 토글)
2. 아카이브된 뉴스 확인 → 주간 뉴스
3. 트위터 인사이트 → 더미 데이터 확인
4. 관리자 페이지 → 뉴스 관리 → 수동 크롤링 실행
5. 삭제 모달 → 소프트 삭제 → 감사 로그 확인

### 포트폴리오&투자자비교 (5분)
1. 포트폴리오 분석 → 이미지 업로드 → OCR 결과
2. 증권사 선택 → 티커 매핑 확인
3. TOP 3 투자대가 매칭 결과 확인
4. 관리자 페이지 → 13F 데이터 수집 시작
5. 투자자 비교 → 4명 선택 → AI 포트폴리오 생성
6. 원형 차트 시각화 → Exposure 정규화 확인

## 🎤 발표 팁

- **속도 조절**: 핵심 기술은 천천히, 시연은 빠르게
- **숫자 강조**: "월 80만 원", "초당 9회", "코사인 유사도 40%"
- **손동작**: "외부 API"는 바깥쪽, "내부 처리"는 안쪽 가리키기
- **시선 처리**: 화면 보면서 설명 → 청중 보며 핵심 강조
- **질문 유도**: "왜 AI를 안 썼냐"는 예상 질문을 미리 답변
